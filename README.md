# Telegram-бот «Клуб Романтики»

Рабочий каркас Telegram-бота на aiogram 3 для каталога историй, сезонов, серий, гайдов, персонажей, избранного, подписок, новостей, поиска и базовой админ-панели.

## Почему aiogram

Проект использует aiogram, чтобы бот запускался только по токену от BotFather. `API_ID` и `API_HASH` с `my.telegram.org/apps` не нужны.

## Архитектура

- `bot/handlers` — команды и callback-навигация Telegram.
- `bot/keyboards` — inline-кнопки и меню.
- `bot/database/models.py` — SQLAlchemy-модели.
- `bot/database/repositories` — запросы к базе.
- `bot/services` — поиск, рекомендации, уведомления.
- `bot/states` — простые runtime-состояния для поиска и админских сценариев.
- `scripts` — служебные скрипты, включая тестовое заполнение базы.
- `migrations/schema.sql` — SQL-схема для SQLite и ориентира при переносе на PostgreSQL.

Контент хранится в реляционной базе данных, а не в коде. Для разработки используется SQLite через async SQLAlchemy.

## База данных

Основные таблицы:

- `users` — пользователи, Telegram ID, язык, спойлеры, уведомления.
- `stories` — истории, описание, жанр, статус, обложка.
- `seasons` — сезоны истории.
- `episodes` — серии сезона.
- `choices` — выборы, стоимость, последствия, теги, спойлеры.
- `parameters` — настраиваемые параметры истории.
- `characters` — персонажи.
- `romance_routes` — романтические ветки.
- `updates` — новости и обновления.
- `favorites` — избранное.
- `subscriptions` — подписки на истории.
- `progress` — прогресс прохождения.
- `ratings`, `reports`, `achievements`, `user_achievements` — расширяемые функции.

Полная SQL-схема лежит в `migrations/schema.sql`, актуальная ORM-схема — в `bot/database/models.py`.

## Пользовательские сценарии

1. Пользователь открывает `/start` и попадает в главное меню.
2. Нажимает `Истории`, выбирает историю, сезон и серию.
3. Открывает гайд и фильтрует выборы: все, алмазные, романтические, параметрические, критичные.
4. Меняет режим спойлеров в настройках.
5. Добавляет историю в избранное или подписывается на обновления.
6. Ищет историю, персонажа или выбор через глобальный поиск.
7. Открывает персонажей выбранной истории.
8. Администратор добавляет историю, смотрит статистику и отправляет рассылку.

## Создание бота через BotFather

1. В Telegram откройте `@BotFather`.
2. Отправьте `/newbot`.
3. Укажите название и username бота.
4. Скопируйте выданный токен.
5. Для удобного меню можно выполнить `/setcommands` и добавить:

```text
start - главное меню
help - помощь
search - поиск
favorites - избранное
settings - настройки
updates - обновления
admin - админ-панель
```

## Установка локально

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`:

```env
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=ваш_telegram_id
DATABASE_URL=sqlite+aiosqlite:///./club_romance.db
LOG_LEVEL=INFO
```

## Заполнение базы тестовыми данными

```bash
python -m scripts.seed_data
```

Скрипт можно запускать повторно. Он добавляет и обновляет только официальные игровые обновления с ссылками на источники. Истории, сезоны, серии и гайды добавляются отдельным импортом GamesIsArt.

Раздел `Обновления` показывает новости самой игры «Клуб Романтики», а не изменения этого бота. Для стартового наполнения используются официальные источники: официальный Telegram-канал игры и страница приложения в App Store.

## Импорт структуры гайдов GamesIsArt

Чтобы заполнить истории, сезоны и серии по странице GamesIsArt, запустите:

```bash
python -m scripts.import_gamesisart_guides
```

Скрипт читает страницу `https://gamesisart.ru/guide/Romance_Club_Prohozhdenie.html`, находит истории, сезоны и серии, сохраняет их в базу, добавляет ссылку на источник к каждой серии и автоматически извлекает пункты выборов: алмазные траты, параметры, отношения и важные последствия. Старые заглушечные истории, созданные прежним `seed_data.py`, удаляются автоматически. После импорта пользователи видят гайды прямо в боте.

## Запуск в Docker (Рекомендуемый способ)

Проект полностью готов к контейнеризированному запуску:

```bash
# 1. Настройте файл .env
copy .env.example .env

# 2. Запустите стек через Docker Compose
docker compose up -d --build

# 3. Проверьте логи
docker compose logs -f club-romance-bot
```

## Проверка готовности к запуску (Pre-flight Check)

Перед запуском бота выполните скрипт предстартовой проверки:

```bash
python scripts/preflight_check.py
```

Скрипт проверяет версию Python, установленные пакеты, конфигурацию `.env`, целостность базы SQLite (58 историй, 144 сезона, 1 613 серий, 53 236 выборов) и доступность Telegram Bot API.

## Запуск локально

```bash
python -m bot.main
```

После запуска откройте бота в Telegram и отправьте `/start`.

## Запуск на VPS (systemd)

1. Установите Python 3.10+.
2. Скопируйте проект в `/opt/club-romance-bot`.
3. Создайте виртуальное окружение и установите зависимости:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
4. Создайте и настройте `.env`:
   ```bash
   cp .env.example .env
   ```
5. Установите готовый systemd-юнит:
   ```bash
   sudo cp deployment/club-romance-bot.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now club-romance-bot
   ```

## Резервное копирование базы (Online Hot Backup)

Для безопасного горячего резервного копирования без остановки бота используется SQLite Backup API:

```bash
# Ручной запуск (сохраняет до 10 последних копий в backups/)
python scripts/backup_db.py --keep 10
```

Для периодического резервного копирования добавьте задание в `crontab -e`:

```cron
0 */6 * * * /opt/club-romance-bot/.venv/bin/python /opt/club-romance-bot/scripts/backup_db.py --dir /opt/club-romance-bot/backups --keep 20
```

## Инструкция администратора

Админом считается пользователь, чей Telegram ID указан в `ADMIN_IDS`.

Доступные функции:

- `/admin` — открыть админ-панель.
- `Добавить историю` — пошагово ввести название и описание.
- `Статистика` — посмотреть пользователей, истории, серии, выборы, избранное и подписки.
- `Рассылка` — отправить сообщение всем пользователям после предпросмотра.

## Безопасность

- Токен хранится только в `.env` и исключён из Docker-образа (`.dockerignore`).
- Непривилегированный пользователь `botuser` внутри Docker-контейнера.
- SQL-запросы выполняются через параметризованную SQLAlchemy.
- Ошибки логируются с ротацией логов.
